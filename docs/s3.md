# `serve-s3` and `serve-ssm`

Two AWS SDK-backed modes with KDL policies in their own grammar, not the `wrap` inline one, so [`lint`](serve.md) does not cover them.

## `serve-ssm <spec.mcp.kdl> --http :addr`

The exact-parameter reader. Its policy names one parameter and grants exactly `get_parameter(name)` plus `get_forgejo_read_token()`. The tool rejects every other name before AWS sees a request, and IAM independently limits the workload principal to the same parameter ARN, so a mistake on one side leaves the other holding. The readers advertise read-only, idempotent behavior and a structured output schema.

## `serve-s3 <spec.mcp.kdl> --http :addr`

The asset publisher, and the first write-capable mode. Its policy fixes one bucket, the media types it serves, the public base URL it returns, and an optional key prefix.

```kdl
wrap ward mcp aws s3 {
    region "us-east-1"; bucket "coilysiren-public-assets"; base-url "https://files.coilysiren.me"
    prefix "dowel"; max-bytes 8388608; content-type "image/png"; content-type "application/json"
    can put object; can list objects; can get object-url
}
```

The policy must grant all three tools: `put_object(key, content_base64, content_type)` returns the public URL, `list_objects(prefix)` lists inside the policy prefix, and `get_object_url(key)` confirms existence and returns the URL.

**Why the guardfile carries more than IAM.** The caller supplies bytes, key, and content type, and to IAM every `PutObject` in the bucket looks alike, so these bounds live only here:
- **Content type is an exact allowlist.** The parser refuses `text/html`, `image/svg+xml`, and other markup a browser executes in the origin's security context, since an uploader could otherwise script against a hostname that also serves other work. SVG is the non-obvious one. A guardfile listing one fails to start.
- **Keys are letters, digits, dash, underscore, dot, and slash**, with no traversal and no empty segments. A key is a public URL path, and an escaped one round-trips differently through a CDN, a listing, and a linkifying chat client, so it is refused.
- **Size is capped from the decoded bytes**, never a stated length. `max-bytes` defaults to 8 MiB.

**What it cannot do.** There is no delete tool, and the workload user's IAM withholds `s3:DeleteObject` rather than relying on that absence. `put_object` overwrites, so the bucket keeps versions to recover. It advertises `readOnlyHint: false` and `idempotentHint: false`, since the same key twice serves different bytes.

**The URL is the CDN's.** The bucket is private and readers go through CloudFront, so `base-url` is the distribution hostname. An S3 URL would 403 for every reader.

**Feeding it bytes.** Bytes arrive base64 in the call, so it suits what an agent generates itself, such as a chart or a JSON export. It cannot chain from an image another tool returned, since that reaches the model as content, not text it can re-emit. See [serve.md](serve.md).
